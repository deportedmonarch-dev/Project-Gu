# RFC 0007 · Alpha 6 Wild Gu Ecology

**Status** — Approved architecture with owner amendments, closed for research handoff. Gameplay implementation awaits authorization and Alpha 5B acceptance. Research baseline `d82c723769ab19dd9078ba3dfefd0a20ee8d10ce`, RimWorld `1.7.5014 rev1195`. The Alpha 5B gameplay candidate is `5df38decbc4f0b089267de0d52f66db224ba9b5a`. Its documentation-only closeout records provisional acceptance pending owner playtest. The [baseline and engine audit](ALPHA-6-BASELINE-AUDIT.md) preserves the Alpha 5A evidence. The [readiness review](ALPHA-6-ENGINEERING-READINESS.md) distinguishes confirmed decisions, recommended defaults and open content choices. The [implementation handoff](ALPHA-6-IMPLEMENTATION-AND-VERIFICATION.md) specifies phases and gates.

Use sparse, persistent cohorts to represent wild Gu, with locally sampled habitats and a small number of registry-owned encounters. Preserve the spring's working cohorts and its existing search and lure paths. There should be a predictable relationship between what a player sees in a place, the conditions that sustain those Gu, and which Gu can actually be found. A forest, a desert and a cavern can each have distinct populations even if two of them offer the same discovery mechanic.

The approved initial common roster is **Black Boar Gu, White Boar Gu and Stone Skin Gu**. Start with Black Boar Gu and one owner-confirmed surface habitat. After focused native verification, add White Boar Gu and Stone Skin Gu to exercise the same habitat, population and encounter authorities with different compatible profiles. Species additions should ordinarily require data and species-specific gameplay or presentation components only. The names and rarity establish the roster. Habitat, diet, ability, representation, origin and numerical balance require separate content decisions. [Species decisions](ALPHA-6-ENGINEERING-READINESS.md#initial-roster-and-content-decisions)

### Habitat identity and regional distribution

- **Regional suitability** uses coarse inputs from biome, world layer, region/landscape tags, elevation/hilliness, seasonal climate and optional hydrology. A stable project-defined rule maps nearby surface tiles with comparable geography to distributions. The first slice can evaluate per tile with a seeded regional modifier. It does not need a saved row for every tile or a world-generation patch. Support underground site presets using the saved surface geography plus underground-specific traits and climate from the level itself.
- **Local occupancy** is one row per `(HabitatKey, speciesDefName)` initially, with two life-stage counters. A stable locality address and durable slot or named resource-point ID determine `HabitatKey`. Store the selected profile separately so profile or environment changes cannot grant new stock. Surface natural slots can use layer plus tile and a fixed coarse zone ordinal. Underground slots use `GuIndependentSite.SiteId` plus level ID. Each spring in either context adds its own saved habitat ID. A live Map and its generation number are transient access credentials. A regenerated map binds the same rows. A different site on the same tile gets a namespace only through explicit site establishment. Legacy springs use their saved habitat ID and exact native spring binding.
- **Default slot rule.** Start with one coarse non-spring habitat for each eligible map and only one qualifying loaded map per locality. Add slots when there is verified need for spatially distinct ecology. If matching profiles overlap, choose one by authored priority then stable Def name for each slot and each claim on a physical resource. The winning profile and slot allocation are recorded once. Runtime habitat degradation adjusts quality. It cannot silently switch keys or seed new stock. Any split/merge or migration of habitat identity is transactional and versioned.
- **Separate ownership for large regions.** Alpha 6 delivers sparse regional populations and unloaded locality recovery after the first surface slice. A regional suitability roll carries zero headcount. A realized regional cohort is a separate, finite pool. It may supply explicit migration or recolonization into local rows. Each moved Gu has one count owner at a time. Transfer debits and credits in one transaction with compatible habitat, rank and stage. Derive stable regional keys from saved world geography and layer without creating neighbor maps or rows for every tile.
- **Initial stock.** Persist the initialization decision even if the result is zero. First occupancy uses a stable seed and a documented one-time origin or a draw from a regional pool, with one source for each unit. Use world seed, locality/slot, initial profile version and species in deterministic order. Reload, map replacement, rebuild, relocation, missing Def restoration and profile edits reuse that decision. Preserve legacy spring ownership and missing-Def rows. Key changes require an explicit migration or alias. A genuinely different spring must pass the independent establishment checks below.

### Establishment and changing habitat suitability

Keep initialization, establishment, abundance, replenishment and suitability independent. An uninitialized scope has no committed decision about initial occupancy. An initialized but absent species has zero eligible stock and no establishment evidence. An established population has a committed establishment and eligible resident or cohort stock. Depletion means an established population has reached zero eligible stock. The recovery latch and current suitability remain separate in each case. For example, a depleted population can be latched for recovery while an invalidated habitat blocks additions. Persist the initialization decision even if an absent species uses a compact marker instead of an empty row.

Initialized-empty and later-depleted states block repeated free initialization. Both may receive an authorized colonization event when the species now passes hard eligibility and there is headroom. Migration debits a finite donor, formation uses a declared creation rule, and deliberate introduction changes membership while preserving an existing Gu's ID. Revalidate current suitability, exact source and recipient revision before committing the incoming unit and establishment evidence. The habitat becoming suitable by itself grants no Gu. Persist evidence across map removal, reload, profile changes and temporary invalidation. Previously absent species are valid colonization targets under these rules.

### Cohort updates

The owner set a balance target of one ordinary replacement per **3–9 in-game days** under favorable conditions in RimWorld's roughly **60-day year**. Tune intervals per species and habitat and verify them in play. Founding an eligible artificial breeding habitat may establish its initial pair in **approximately 1–2 days**. These are initial balance targets. Multi-year waiting is outside the ordinary baseline.

1. Apply hard geographic and environment eligibility before weights or capacity. Compute `K` from measured habitat and resource signals. Compute `N` as anonymous mature + juvenile units plus eligible linked living wild residents of this population, counted once. A projection is included through its membership, never as an extra anonymous unit. Capture, death, disqualifying possession or permanent departure removes its membership contribution. A presentation-only body retirement retains occupancy if the individual remains an eligible resident. Ambiguous membership or missing measurements suspend credit until resolved.
2. Apply explicit bounded mortality and stage transitions before recovery. A valid observation with `N ≤ populationMin` activates the saved cycle and sets its next opportunity. Continue above minimum until `N ≥ min(populationMax, K)` at a valid, eligible snapshot. Suspend an active cycle if habitat eligibility or evidence is temporarily unavailable. No units are deleted when capacity drops. If an eligible habitat reaches its lowered effective target, the cycle may close. A subsequent cycle uses the same activation threshold. Revalidate occupancy and free capacity immediately before each committed addition. Retain legacy spring cadence under its adapter.
3. Each scheduled opportunity resolves one admissible source, with the ordinary target of one replacement unit per favorable interval. Migration or recolonization debits an existing donor and credits the receiver. Abstract natural replenishment or natural formation uses a declared environmental origin and habitat evidence. Formation can be a specific event requiring a distinct profile condition. True offspring require a compatible artificial species and satisfied breeder/environment rules. Maturation moves a unit between stages at zero net count. Seasonal, human or animal influence can alter the snapshot, carry an introduction, or cause an explicit release/escape event. Those influences confer no implicit Gu credit. When nothing can lawfully supply a unit, keep the cycle pending and schedule bounded re-evaluation.
4. Persist cycle state, due time, ordinals, attributable inputs and count/revision changes in one commit. Bump the saved state version when the latch or cursor changes even with zero population delta. Use stable event identity such as habitat, species, cycle and ordinal. Replaying an epoch, loading a map, toggling habitat validity, or rebuilding around a depleted ledger cannot reset the interval or create a new founding event. A blocked interval cannot generate a backlog of unearned replacements. Preserve the cursor on map removal. Loaded and unloaded paths share one clock and ledger. Stagger and budget all work.

### Artificial propagation and deliberate introduction

Historical invention and individual origin answer different questions. An artificial species can establish itself and reproduce in the wild wherever its explicit requirements are met. Naturally occurring Gu generally recover through abstract recruitment, formation or transfer. The framework requires no universal mating, pregnancy, genetics or native animal breeding systems.

An eligible new breeding habitat may use a single **founding pair** event if its species and profile permit it. The recommended default, pending owner confirmation, requires a genuinely new independently identified breeding habitat, room for the pair and documented species-specific provenance for both units, including any required precursor or introducer. Persist the due state, then consume the entitlement with the qualifying establishment receipt. Existing introduced Gu count as founding stock and retain their IDs through custody and membership transitions. They earn no duplicate free units. Temporary invalidation, replanting, relocation, reload and depletion retain the original entitlement and its spent history. Ordinary recovery uses the 3–9-day target where a source is eligible, including incoming Gu or approved formation when no breeders remain. True reproduction waits for its approved breeders and conditions. No compatible source means the site stays depleted. Unique Gu and Immortal Gu have no implicit reproductive eligibility.

Owner examples constrain future profiles without defining unimplemented Gu. A compatible Moonlight Gu profile can require a spirit spring, qi-rich or dense soil and Moon Orchids. Applicable Blood Path Gu can depend on abundant blood, flesh, blood pools or corpses. Compatible artificial Bone Path Gu associated with the Bone Scholar can depend on a milk spring. Treat these as species-specific policy and read-only signals. Deliberate introductions and qualifying artificial habitats provide the later farming path for colonies, institutions, blessed lands and immortal economies.

### Spirit spring profiles and independent ownership

Reserve the authored Moon Orchid cavern configuration for an appropriate Gu Yue scenario, approved cultivated habitat or development fixture. Keep established Alpha 5B springs and their actual stocks, flora, reserve, support, route, receipts and histories under their existing profile. The pinned [cavern GenStep](../Source/ProjectGu/Underground/GenStep_GuSpringCavern.cs), [spring initialization](../Source/ProjectGu/Springs/CompGuSpiritSpring.cs) and [spring Def](../Defs/ThingDefs/GU_SpiritSpring.xml) currently supply that specialized default. Extract a data-selected profile in a later slice. For new ordinary springs, resolve hard eligibility from exterior geography and cavern conditions such as water, stone, qi, soil, temperature and roof, then weight only eligible flora and Gu. No match means no incompatible pick. Provide extension slots for Earth Path, Water Path, stone-associated Gu, hibernating specimens and underground flora as approved content becomes available.

Each independently established spring has one durable resource-point identity and separately owned cohort rows, even on a shared map or within one site. Grant initial establishment only through an authored/discovered world occurrence or validated cultivation operation with independent source evidence and support. A new Thing, profile or player-designated slot alone cannot create that claim. Bind repeated discoveries, rebuilt anchors and regenerated maps to the original ID, including retired/empty establishment markers. Keep the persisted site/level/route graph of `GuIndependentSite` and the stable spring habitat ID. Reuse the deterministic exclusive attribution in `GuEcologyMapComponent.HabitatOwnerAt` as the starting pattern for overlapping support cells and add stable identity tie-breaking for new ownership. One finite support signal is attributed once or apportioned under a documented shared budget. Two valid springs can have the same compatible species with independent populations and recovery histories. Duplicate ID claims stop mutation while retaining evidence.

### Future resource-point relocation

Milk springs are specialized inheritance-associated resources. Define a future excavate, pack, transport and re-establish operation that carries the same resource-point ID, population ownership, committed-origin history and founding/recovery state through native custody or a durable transit claim. The source is deactivated before the destination becomes authoritative. A lost, interrupted or failed move preserves the sole valid claim and never leaves a second functional point. The destination updates geography and revalidates specialized habitat conditions before breeding resumes. Persistent individuals may move only through their own valid custody or membership transition. A relocation grants no fresh stock, entitlement or elapsed production credit. This contract can later support other cultivation resources and blessed lands, including maintaining compatible Bone Path Gu at home. Excavation, transport and placement mechanics are deferred.

## Population and individual lifecycle

### Four independent facets

| Facet | Authority and effect |
| --- | --- |
| Identity | `GuRecord.Id`, species, rank, existence and provenance belong to the registry. A new ID is issued on a committed individual creation and persists through captivity, release, WorldSite and projection replacement. A compacted tombstone preserves the ID's accounting and replay evidence. |
| Ecological membership | Record an optional `(habitatKey, species, lifeStage, membershipRevision)` for a living, linked wild resident. Membership authorizes demographic presence and is distinct from immutable origin and the current observed position. One linked individual is counted in at most one habitat's resident index, separate from its anonymous stock. A visit, temporary excursion or release does not assign membership automatically. Establish or move it through an approved ecological event. |
| Custody | Canonical registry placement authorizes a manifestation or record-only container. The native holder graph supplies physical possession and position for projections. Refinement allegiance is an independent state facet. Capture, transfer or escape can change custody and clear/reassign membership with no headcount change. |
| Manifestation | A native Pawn, Thing, or absent projection is a representation authorized by a record and custody revision. A transient hint or sprite represents an observation opportunity without an individual binding. A healthy active Gu can have record-only custody. Body replacement and absence leave the Gu's identity intact. Validate legal combinations per adapter when extending V2's current Pawn/active and Thing/dormant checks. |

The population owner's repeatable count is `anonymous mature + anonymous juveniles`. `Living linked residents` is a separate derived occupancy counter for local capacity and habitat pressures. A departure clears the resident link or marks an explicitly allowed excursion while the living ID stays counted on the individual side. Captured, released and abstracted individuals can have a known origin without membership. Audits count unresolved debited records once, while unusable or ambiguous membership is excluded from fast demographic decisions until reconciled.

### Conservation ledger

For reconciliation over a fixed species/rank scope, `opening cohort units + opening living individuals + declared creation + imports = closing cohort units + closing living individuals + deaths + consumptions + exports + explicit retirements/loss`. Declared creation records the actual mode, including replenishment, formation, one-time initialization, founding or authorized artificial reproduction. An import debits an accountable donor. An unresolved-but-debited record is still one living individual. An unauthorized projection or undebited quarantined shell contributes zero. A committed materialization transfers `−1 mature / +1 individual`. A committed return transfers `−1 individual / +1 mature` at the destination. A replay is zero delta. Cohort maturation conserves total counts. A deliberate transformation or cross-scope migration is an explicit debit/credit pair. Direct Hope consumption in awakening remains a legitimate sink without first creating a record. Captured or introduced existing Gu retain their global count and change wild occupancy only as eligible membership changes.

Record commit evidence carries stable event and source/destination identifiers, species, stage, origin/transfer mode, delta, epoch and revision. Use checked counters, canonical main-thread mutation, and a custody/save barrier through native callbacks and final binding. Keep persistent evidence compact using an event high-water mark and durable rollups for deterministic internal changes where proof and replay protection survive. Retain cross-authority and founding receipts or canonical tombstones, so a missing row, extinct cohort, save reload or subsequent revision never makes the same key reusable. Retry the same payload by receipt before testing its stale revision. Return a conflict for a reused key with different source, trigger, species or asset scope. Replanning against a changed habitat may use the same uncommitted request under one new validated plan. A historical receipt can describe an ended/unresolved individual with zero new effect.

The registry source handle should carry `ownerKind`, `habitatKey`, an exact source instance credential (spring native ID or live map generation token) and `expectedCohortRevision`. Save and compare the stable source identity in receipts. The live credential guards against stale objects and is reacquired after load. An accepted record carries its original creation event, exact source, debit proof and originating species/rank. A return receipt adds the previous Gu ID and custody revision, destination key and revision, result delta and ending tick. A habitat needs a read-only lookup and a prepared mutation with checked revision and value. Centralize mutation ordering under the registry lock and guard callbacks. The initial new-source origin can use a separate origin subtype or additive provenance fields to preserve validation of historical records whose `OriginNativeId` necessarily names a spring Thing.

Add approved leased dematerialization and returns as a later slice. Use the saved lease's locality as the default destination and permit another destination only by an explicit habitat route. Persistent wounds, native ownership, capturer interest and active quest references can prevent return. Keep the counted individual if retirement is unsafe. During abandonment, RimWorld can transfer a wild Pawn to `WorldPawns`, which fails the current `CanRetire` check. Preserve that individual's placement through existing reconciliation until a separate world-custody return adapter proves safe removal and callback classification. A passing map lease fixture alone does not establish that capability.

**Implemented in Slice 0 (after the independent review).** The registry never authorizes a source from the adapter it is handed. It resolves the one live source for `(ownerKind, sourceId)` through `IGuPopulationSourceDirectory`, implemented by the component that already owns and saves that kind of source (springs: the map's ecology component). The supplied adapter must be that exact owning binding. Each cohort row carries owner-side debit evidence: the count of receipt-backed debits, a chained digest of `(revision after, event key)` in commit order, and a seal over its state. The registry recomputes the chain from its receipts in preflight, after native callbacks and at load once both owners are ready. A substituted, regenerated, edited or duplicated scope is frozen, with no credit, deletion or adjustment. Historical rows and records keep their rules. Lure bait is a transaction asset spent once inside the custody guard, and its outcome (`Settled` or `Interrupted`) is durable on the receipt. [Corrections](ALPHA-6-SLICE-0-CORRECTIONS.md)


### Significance and retention policy

Default to preserving a canonical individual. A species must opt into anonymity for common wild encounters, and the current member must have valid origin/debit, membership and destination evidence. Require a minimum unseen interval, no current pursuit, queued job or target reservation, a safe native retirement, and no personal state that would be erased. Lock the event and recheck the complete eligibility at commit.

Promote to persistent significance on completed capture, ownership/transfer, refinement, a unique or protected rare occurrence, quest or social linkage, intentional naming/tagging/tracking, or another event with a future individual reference. Treat player or NPC custody and an escape from it as persistent even when allegiance is still absent. Rare and unique, high-rank and unresolved individuals default to retention. In the proposed default, a fleeting sighting or ordinary inspect view records an observation and does not alone make an individual irreplaceable. Return preserves the tombstone and event evidence, so later emergence from the cohort issues a new ID. Significant living records retain the facts necessary to track, recover or act on them, with narrative aging handled under existing registry retention policy.

### Save and teardown ordering

1. Save versioned population and intent state with the game. Persist initialized-empty localities, string Def names, timestamps/seeds, checked counts, in-flight **durable intents** (e.g. a search job) and the minimal evidence for leases and committed transfers. Active leases reference Gu ID and no duplicate binding. Keep queues, habitat observations, sprites and reservations that can be reacquired transient. Bar saves during synchronous native staging/commit and establish the same barrier for return. Drain ecology-affecting lifecycle events before any authority is serialized using the existing save guard, and verify both save entry points. Cross-owner reconciliation must finish before the first writer runs. An `ExposeData` fallback must refuse a still-changing save rather than credit a cohort after its owner has written.
2. After Scribe references resolve, validate receipt shapes, IDs, stage/state and duplicate ownership. Rebuild registry and habitat indexes without spawning or crediting. ### Ecological truth and in-world knowledge

Keep habitat counts, conditions, rare-specimen IDs, availability and receipts inside simulation authority. Pawn AI, player navigation and future Society Core query permitted observations or universal habitat lore. An observation carries an observer ID (pawn or faction), a coarse location or observed feature, time, species or suspected class, source/method, confidence and age. Include an individual reference only where the actor has earned one, such as tagging, tracking or custody. A direct sighting, exam, scout report, quest clue or explicitly shared teaching can create or convey an observation. Faction membership alone supplies no live population or coordinate feed. Faction aggregation of reports and recall limits can evolve separately.

Choose searches using belief and visible habitat, then let the coordinator test actual eligibility when an actor reaches the site. Stale or erroneous beliefs can yield no result and be corrected by a new observation. A query or unsuccessful trip never returns hidden counts or coordinates as a side channel. Existing Alpha 5B installed spring inspection is a local, player-facing disclosure on that observable object. It does not publish all ecology facts to external AI. Presentation reads outputs approved for its viewer and cannot grant knowledge on render or inspection calls alone. Fixture requirements include observer isolation, stale reports, explicit sharing, hidden rare occurrences, and the distinction between observed absence and unknown.

### Independent Gu and vanilla wildlife populations (owner requirement)

Project GU's ecological populations coexist with ordinary RimWorld wildlife. They never displace vanilla animals or consume their population budget, and Project GU keeps its own population accounting. Exclusion from vanilla generation pools does not prove this, because a manifested Gu inherits animal Pawn infrastructure. The Alpha 6 Slice 0 correction pass audited the pinned engine (`1.7.5014 rev1195`, `Assembly-CSharp` decompiled with ILSpy 11.2) and measured it natively.

| Engine path | Pinned behavior | Gu effect |
| --- | --- | --- |
| Current occupancy (`WildAnimalSpawner.CurrentTotalAnimalWeight`) | Sums `kindDef.ecoSystemWeight` over every spawned Pawn whose `Faction` is null. This is the engine's only gameplay consumer of `ecoSystemWeight`; the others are debug outputs. | Wild Gu are factionless, so they are counted, but every Gu kind inherits `ecoSystemWeight` 0 from `GU_WildProjectionKind`. The registry factory (`HasNativeGenerationExclusions`) refuses to generate a kind with any other weight. **Contribution: zero.** |
| Desired occupancy and density (`DesiredAnimalDensity`, `DesiredTotalAnimalWeight`) | Tile animal density × the share of `map.Biomes` wild-animal commonality acceptable this season × game conditions × pollution, scaled by map area. No Pawn is read. | None. Mixed-biome maps average over `BiomeDef.AllWildAnimals`, which never contains a Gu kind (`wildBiomes` empty, no `wildAnimals`, pollution or coastal entry). |
| Ecosystem gate (`AnimalEcosystemFull`), initial generation (`GenStep_Animals`), periodic replenishment (`WildAnimalSpawnerTick`) | Map generation fills until full; every 1213 ticks a seeded chance spawns a biome animal unless full. | Gate unchanged by Gu, because occupancy is unchanged. Gu are never spawned by either path. Cohorts stay abstract until the registry materializes one. |
| Species commonality (`CommonalityOfAnimal`, `CommonalityOfAnimalNow`, tile mutators) | Biome lists plus race `wildBiomes`. | Gu kinds have no commonality anywhere (asserted for every loaded biome). |
| Herd migration (`IncidentWorker_HerdMigration`) | Spawns new animals of a kind with `CanDoHerdMigration`. | Gu: `herdMigrationAllowed` false. Vanilla has no population-driven departure of existing wild animals. |
| Predator prey (`FoodUtility.IsAcceptablePreyFor`) | First gate is `canBePredatorPrey`. | Gu: false, so predators never select a Gu (asserted against the strongest eligible predator). |
| Manhunter packs, quests, trade, pets | `canArriveManhunter`, `neverIncludeInQuests`, tradeability, petness. | All excluded (existing `GuGeneration` profile and the factory gate). |
| Hunting designation, taming, animal insanity, self-tame incident | `Designator_Hunt`: factionless animal. `TameUtility.CanTame`: wildness < 1. `AnimalInsanityMass.AnimalUsable` / `AnimalInsanitySingle`: factionless spawned animal. `IncidentWorker_SelfTame`: factionless animal with wildness > 0, then `SetFaction(player)`. | **Eligible (inherited, pre-existing).** None of these touches population accounting, but taming and self-tame change a wild Gu's faction outside the registry's custody transactions. Recorded for owner prioritization and as a Slice 1A gate below. Not changed in the Slice 0 correction pass. |

**Native controls** (`Slice0Wildlife` profile). A fresh clan start's home map has its factionless population replaced by one biome species, filled to just below the desired weight. Measured with the engine's own private properties:

- **Negative control.** Sixteen registered, factionless, manifested wild Gu of four species leave current weight, desired weight, density, the ecosystem-full gate and the ordinary count bit-identical. The engine's weight equals the same sum with the Gu terms left out.
- **Positive control.** One more ordinary animal raises the weight by its `ecoSystemWeight` and closes replenishment. Removing it restores the measured state exactly.
- **Replenishment.** The engine's own `WildAnimalSpawnerTick` runs at a spawner interval under a fixed `Rand` seed. The same seed replenishes the same species and group size with the Gu present and after every Gu is removed.
- The spring-cavern control checks occupancy weight. The fresh-process control checks exact registered identities, occupancy, desired weight and continued eligibility for replenishment.

**Decision.** Existing projections do not affect native wildlife population accounting, so no production correction is needed in this pass. The narrowest seam is already in use: per-kind `ecoSystemWeight` = 0, enforced by the registry factory, with no Harmony patch on the spawner. If a future Gu-beast must take part in wildlife ecology, that is an intentional, explicitly owned interaction through Project GU ecology. Inherited animal accounting is never the mechanism. A third-party mod that adds a Gu kind to a biome's lists or raises its weight is a diagnosed configuration conflict: the factory refuses such a kind, and `GuGeneration` asserts pool exclusion.

**Mandatory Slice 1A acceptance gate.** Any new wild Gu Pawn (Black Boar Gu first) must pass `Slice0Wildlife`-equivalent controls with its own kind: zero occupancy contribution, unchanged desired weight, density and full gate, matched-seed replenishment, and pool, prey, migration and manhunter exclusion. The inherited hunt, tame, insanity and self-tame eligibility needs an explicit owner decision for each path (intended Gu interaction, or blocked as accidental inheritance) before the species ships, alongside the existing native physiology gates.
