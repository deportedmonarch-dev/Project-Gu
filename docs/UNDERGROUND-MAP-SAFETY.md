# Persistent underground map safety

This is the pre-implementation audit of native pocket removal. Its call chains and design options record the investigation that led to Priority 0. The current implementation uses independent ownership for new spring levels and pre-mutation guards for legacy pocket dependencies. [Current lifecycle policy and live acceptance](UNDERGROUND-INDEPENDENT-LEVELS.md).

**Legacy prototype decision.** Retain a settlement with dependent native pockets until a verified operation can preserve those sites. The original probe detects invalid bindings and closes travel after unexpected removal. Priority 0 adds the pre-mutation protection described in the implementation report.

## Installed call chains

Evidence comes from the Windows RimWorld 1.7.5014 rev1195 assembly. These are static call-chain findings. No destructive operation was run against an existing save.

| Path | Order and mutation | Earliest useful intervention |
|---|---|---|
| Explicit player abandonment | `SettlementAbandonUtility.TryAbandonViaInterface(MapParent)` opens confirmation. Its private `Abandon(MapParent)` calls virtual `MapParent.Abandon(bool)`. The `Settlement.Abandon(bool)` override runs base and can add an abandoned world object afterward. Base also applies colony-transition effects before `WorldObject.Destroy()`. | Guard before opening confirmation for feedback and at the actual commit against stale UI. A prefix on only the base method can leave the derived post-base logic running. |
| World-object destruction | `WorldObject.Destroy()` calls `WorldObjectsHolder.Remove(WorldObject)` while spawned. The holder removes the entry and its caches before calling virtual `MapParent.PostRemove()`. `Destroy()` subsequently marks the object destroyed and notifies factions and quests. | A guard on the holder alone lets the caller continue. A map-only guard still leaves the holder mutation. Intercept the relevant caller before the operation starts. |
| Automatic map removal | `MapParent.CheckRemoveMapNow()` calls virtual `ShouldRemoveMapNow(out bool)`, then `Game.DeinitAndRemoveMap(Map, bool)`, and may then destroy the parent. Tick intervals and caravan reform both reach this check. `Settlement.ShouldRemoveMapNow(out bool)` already keeps a player-home map and checks local blockers. It has no project-dependency extension point. | A targeted eligibility guard could return false for a genuinely dependent source. Automatic polling should stay silent. A distinct, user-initiated rejection can explain the dependency. |
| Gravship source abandonment | Odyssey's `RitualOutcomeEffectWorker_GravshipLaunch.Apply(float, Dictionary<Pawn,int>, LordJob_Ritual)` reaches `GravshipUtility.PreLaunchConfirmation(Building_GravEngine, Action)` for the destructive branch. `WorldComponent_GravshipController.TakeoffEnded()` calls `GravshipUtility.AbandonMap(Map)` if the source lacks an anchor. That utility applies left-behind effects and despawns or passes pawns to the world before calling `MapParent.Abandon(true)`. | Validate the destructive launch before the operation starts and again at the takeoff entry point `WorldComponent_GravshipController.InitiateTakeoff(Building_GravEngine, PlanetTile)`. Preserve anchored launch behavior. A prefix at `MapParent.Abandon` would arrive after pawn changes. |
| Colony reset | The Ideology new-colony quest's private `QuestPart_NewColony.InitMoveColony(List<Thing>, PlanetTile)` queues a continuation that calls `MoveColonyUtility.MoveColonyAndReset(PlanetTile, IEnumerable<Thing>, Faction, WorldObjectDef)`. The utility ends quests and changes pawn ownership before it clears map factions, deinitializes maps and destroys their parents. | Reject quest acceptance or the reset transition before any quest and pawn mutation. The continuation immediately reads the returned settlement's map, so returning null at the reset utility is unsafe. |
| Direct map teardown | `Game.DeinitAndRemoveMap(Map, bool)` first calls the void `MapParent.Notify_MyMapAboutToBeRemoved()`, deinitializes the map and removes it from the game list. It then calls `MapComponent.MapRemoved()`, scenario removal and `Notify_MyMapRemoved(Map)`. Finally it can destroy child pockets and disposes the removed map. `PocketMapUtility.DestroyPocketMap(Map)` removes the pocket parent from `World.pocketMaps` before calling it. Developer destroy and regenerate actions call the same lower-level method. | Treat forced debug and exceptional calls as unsupported teardown. Notification hooks are observational. The earliest notification is already after holder mutation when reached from `PostRemove()`. |

`destroyOnParentMapAbandoned = false` keeps a cavern out of the native destruction cascade. It leaves the stale `PocketMapParent.sourceMap` reference. The native storyteller dereferences that source for threat calculations. Related wealth, ship and source searches also depend on it.

The registry now requires the surface parent to remain registered for travel. It checks native source and pocket bindings after map loading, and receives a map-removed notification without polling. It preserves site and level records, does not redirect or delete content, and logs one serious diagnostic per affected site per loaded session when a missing binding is detectable. The post-removal check is not recovery. The base game may still be unsafe once the source is gone.

## Ownership strategy

| Option | Assessment |
|---|---|
| Pre-removal protection | Preferred as the smallest change to the save graph if independently reviewed and proven. Resolve dependencies from saved site records after load and reconcile with `World.pocketMaps`. Never require a living entrance or a present pawn to count a persistent level. Consult the index only at a checked operation, group by source, and fail closed on ambiguous records tied to that source. Bounded traversal, save/load and feedback are straightforward. Complete engine interception spans independent explicit, automatic, launch and quest paths. The installed game has no shared pre-mutation veto and this branch adds no Harmony dependency. |
| Independent world-object parent | Strong fallback if interception cannot be made reliable. `MapGenerator.GenerateMap(..., isPocketMap: false)` can bind a normal map to a dedicated `MapParent`. Base `ShouldRemoveMapNow` returns false, and `MapParent.Map` resolves by parent identity. `WorldObjectsHolder.Add` expects a valid `PlanetTile` and populates layer caches, while a normal map reads biome and tile data from the world grid. World objects and maps save through the engine's world and map graphs. A provider would have to choose valid tile and layer ownership, test tile collisions and world visibility, define incident tags and threat policy, and validate how current travel and item custody work on the new maps. One parent per level can preserve multiple depths without a native `sourceMap` dependency. This requires approval and a separate probe. |
| Reassignment or relocation | Changing the public Scribed `PocketMapParent.sourceMap` is possible at the field level. Safe relocation must rebind the approved surface route and anchor before the original is lost, validate the native parent registration, account for wealth and incident routing and any ship or portal references, then verify save/load. Do not use a tile lookup or arbitrary replacement map. Consider reassignment later for an explicit player-directed operation with both sources live. |

**Review recommendation.** Use one dependency policy shared by explicit commit, automatic eligibility, destructive launch, and colony reset guards if a Harmony integration is approved. A protected operation should show “Cannot abandon settlement: persistent underground locations are still connected.” Exercise commit-time rejection, dependencies loaded from older saves, and unchanged control settlements before enabling normal gameplay. If this coverage proves impractical, prototype the independent provider before considering migration.

## Legacy pocket regression checklist

Use an [isolated game copy](UNDERGROUND-POCKET-PROBE.md#manual-test-setup) with a generated legacy native pocket. Keep a spare settlement and surface colonists so vanilla abandonment restrictions do not mask the guard. Record both maps, site and level IDs, spring reserve and cohort, pawn identity and equipment, and marker items. Use separate named checkpoints for each row. The current native fixture results and independent-level expectations are in the [Priority 0 report](UNDERGROUND-INDEPENDENT-LEVELS.md#verification).

| Case | Expected result when protected |
|---|---|
| Settlement without sites | Normal abandonment completes. A pending unused entrance without a generated level does not create a persistent dependency. |
| Empty cavern | Abandonment is rejected before the settlement or native pocket registration changes. |
| Pawn underground | Abandonment is rejected. Same pawn, inventory, equipment, health and aperture remain in the cavern. The pawn can return. |
| Stored items and altered terrain | All content, spring state and map edits persist. |
| Two legacy sites sharing one source | Either surviving pocket keeps the source protected. IDs and routes remain distinct. |
| Repeated save and load | Repeat the rejection after reload. Neither map or route is duplicated, discarded or regenerated. |
| Lost entrance | Travel closes for that binding. Remaining cavern and contents still count as a dependency. |
| Cancelled or failed travel | Reserve or queue a travel job, cancel before movement or block its destination, then attempt removal. The same pawn remains on the source of the failed trip and the settlement remains intact. |
| Automatic removal and DLC | Exercise caravan reform or non-home eligibility where reproducible. With Odyssey, compare destructive and anchored launches. With Ideology, exercise the new-colony choice without starting a reset on protected data. |
| Forced teardown | Run only on a separate disposable checkpoint. Direct native removal and pocket destruction are covered by the guards. A third-party path that bypasses those entry points may still break a source binding. Discard the run and reload the prior checkpoint if that happens. |
