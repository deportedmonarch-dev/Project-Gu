# Alpha 6 implementation and verification handoff

Implementation starts after owner authorization and Alpha 5B acceptance. The gameplay candidate remains `5df38decbc4f0b089267de0d52f66db224ba9b5a`. The [RFC](RFC-0007-WILD-GU-ECOLOGY.md) defines ownership, conservation and the approved ecology requirements. The [baseline audit](ALPHA-6-BASELINE-AUDIT.md) records Alpha 5A evidence. The [readiness review](ALPHA-6-ENGINEERING-READINESS.md) records the confirmed roster, recommended defaults and separate species content decisions. The delivery order below is proposed.

## Architecture choices

| Choice | Recommendation and tradeoff |
| --- | --- |
| Save location for population counts | Use a sparse GameComponent for natural habitat cohorts and map-local runtime caches. It keeps a stable owner through visit and removal and makes cross-authority commits tractable. Per-map saved ledgers are simpler until a map disappears, when they need atomic escrow, replay and regeneration policy. Anchor comps work for persistent authored objects, so leave legacy spring ownership where it is. |
| Spatial unit | Start with one coarse habitat per authored locality or eligible map. Add stable coarse slots only to support distinct local ecology. Native regions are useful for reachability and cache invalidation, while terrain changes rebuild them and make their IDs unsuitable as persistent owners. A per-cell cohort grid is expensive to save and would make habitat edits a population migration problem. |
| Distribution model | Begin with deterministic suitability and persistent occupancy for one surface locality. Deliver sparse regional and unloaded locality recovery in a named follow-on Alpha 6 slice. Realize finite donor cohorts on demand from stable regional keys. Evaluate eligibility and transfer using world geography without generating neighboring maps or all-world per-tile ledgers. |
| Appearance | Use a small, capped set of real native Pawns plus ambient and clue outputs. A Pawn per Gu gains full interactions with large costs in AI, health, pathfinding and saves. Pure abstract events scale but lose wild presence and capture play. Native wildlife pools bypass cohort ownership and conflict with the existing explicit generation contract. |
| End of a common encounter | Preserve individuals in the first slice. Add a measured, approved return policy with an explicit credit and aggregated tombstone. Routine pawn recreation from a seed alone breaks identity, while permanent bodies for every common encounter accumulate divergent performance and custody costs. |
| Spring rules and ownership | Wrap established springs at the source boundary with legacy ownership and their shipped rules. New springs can use durable rows keyed by spring ID, bound to independent site/level and native anchor. Separate cultivated/authored and ordinary profile selection in its own slice. Existing maps are not reseeded. |

## Performance model and controls

| Cost or failure mode | Control and instrumentation |
| --- | --- |
| Too many cohort updates or giant inactive catch-up | Maintain a due queue ordered by tick and stable key, stagger phases and consume a bounded work budget. Use one shared loaded/unloaded cursor per row. Hold at most one due item per row or compact versioned stale nodes. Coalesce eligible missed opportunities with checked arithmetic and capped windows. Report rows by local/regional scope, oldest due age, work per epoch, budget saturation and native map creations. |
| Fog, construction, harvest or spawn bursts | Deduplicate by dirty bucket, index only opted-in features/cells, and batch invalidation. Process initial classification in chunks. Fast-path non-signal Things. Subscribe only while map context is bound and clean up subscriptions once. Retain a coarse slow refresh for growth that can change without a spawn/despawn notification. For a large map or new content measure sampling before adding a finer spatial index. |
| Reachability and pawn cost | Gate expensive checks behind cheap filters, use bounded candidate cells, prefer stable cached geometry and cross-check reservations at commit. Run native reachability only for likely actors/cells. Give each rule/region a modest active projection cap. Have behavior workers request allowed habitat moves on a cadence through ordinary jobs, with native AI/needs behavior audited per PawnKind. Avoid repeated path requests, especially around impassable riverbanks, sowing or sealed routes. Measure path requests, job starts, active body count and native tick work by kind. |
| Excess allocation and callback re-entry | Reuse buffers per map, compile Def tables once and avoid LINQ closures or allocation of per-candidate lists in hot paths. Do not share mutable buffers across re-entrant callbacks. Confine writes and native calls to the simulation thread. Collect counters cheaply and log only rate-limited diagnostics. Recompute indexes after loading. |
| Save overhead and chronic churn | Index only extant localities and opted-in cohort rows, preserving initialization decisions compactly. Save active leases and only relevant job intents. Retire historical display narrative using existing compaction, and retain minimal replay evidence. An eventual sequence watermark per source may replace individual failed-attempt entries only after stale callers and historical keys can never re-commit. Keep live, terminal and aggregate debit/credit evidence. Measure save bytes by state class, time to save/load/rebuild and record growth per game year. |
| Map retirement and world-pawn retention | Local cohorts remain in their sparse owner, and transient cache work stops. Reconcile real holder transfers before retiring wild bodies. Never keep a map loaded solely for a common cohort or habitat marker. Track existing registry sweep cost as tombstones grow, and consider event-driven, active-only indexes if benchmarks demonstrate starvation of live reconciliation. |

Provisional engineering defaults for the small first fixture are one automatic encounter attempt per locality/rule per in-game hour, one simultaneous projected individual per rule, two ecology-created active projections per map, and a cap of 12 candidate cells per attempt. Use a global budget across maps, for example 32 dirty buckets and 16 due cohort operations per 250 ticks, with an initial classification budget of about 256 cells per 250 ticks per scheduled map turn and rotating priority. These are starting quotas to test. Measure responsiveness and missed deadlines before committing defaults. Detect queue growth under sustained input and coalesce work by key without dropping critical committed events. Returns, saves and confirmed state changes have their own transaction path outside speculative work quotas.

Measure control builds with ecology off versus on using matched saves, seed, mod list, settings and machine. Include sparse untouched geography, one dense colony, multiple loaded levels, bulk discovery, saturated projection budget, dense flora churn and long-running histories. Measure tick median and tail, managed allocations/GC, path calls, projection count, due lag, and fresh-process save/load. Disable overlapping game processes for timing, record hash and environment, and keep performance budgets provisional until measured. Native headless is suitable for correctness and tick comparison. Graphical runs are needed for visibility, rendering cost and player discoverability. A failure due to fixture assumptions needs reproduction and isolation before attributing it to Alpha 6. ## Verification matrix

Use `scripts/verify.ps1 -Focused` during development and the standard suite before integration. New `LiveWildEcology` profiles belong in the existing disposable native runner and test mod. Verify fresh process rather than relying on in-session reload alone. Keep error expectations explicit for deliberately injected failures, preserve original historical save hashes, and document evidence at the candidate commit.

| Case | Method and required observations |
| --- | --- |
| Accounting and schema | Managed tests for zero stock, missing optional Def, invalid/duplicate rows, overflow, capacity fall, stage changes, mortality, one-time seed and materialization, stale revision replay, event collision, distinct historical species and individual origins, and valid reproduction policy. Verify one accounting owner per Gu and the conservation equation after every source/transfer across a long seeded sequence. |
| Recovery threshold and cadence | Use a deterministic fixture, for example minimum 1, maximum 4, capacity ≥ 4 and one unit every 3 days. Start at 1, produce one at each interval, continue through 2 and 3, and stop at 4. Materialization alone keeps total eligible occupancy. Capture/death removes it. Test capacity drop without deletion, temporary ineligibility, source exhaustion, reset/rebuild attempts, stable phase through map removal and fresh reload, and other profiles within the 3–9-day tuning range. |
| Locality and generation | Native new games with matched and distinct biomes or terrain, mixed-biome/unknown context, a generated cavern and a legacy pocket. Initialize exactly once. Save immediately before/after first eligible bind, reload in a fresh process and prove equal seed outcome and state. Include regenerated/empty/native quest maps, competing parents on one tile, paused/closed routes and inactive locality revisits. |
| Absent species and later colonization | Persist an initialized-empty locality, reload and rebuild it with zero samples granted. Change habitat suitability and confirm that eligibility alone adds no stock. Commit an authorized migration, formation or existing-ID introduction, then replay after a fresh load. Check distinct establishment/depletion evidence, one valid credit or membership change and no reset of founding history. |
| Wildlife generation integrity | Rerun `GuGeneration` on Core and Biotech+Odyssey. | Native wild physiology | Run subsistence, curiosity, saved-job and intentional feeding regressions. Give new and migrated Gu Pawns access to eligible plants, food and relevant wildlife around them. Preserve legitimate damage, capture and exact identity. Positive controls exercise native non-Gu feeding and 5B manual/background feeding and timed lure expenditure. |
| Native age, taming and training | Tick new and saved Pawn projections across the approved age/stage boundary. Confirm no unintended canonical maturation, inherited senescence effect or identity change on remanifestation. Exercise designator and job paths, old queued jobs, training queries, and an external faction change. Verify ordinary non-Gu tame/train controls still behave natively. |
| Projection and fault atomicity | In native fixtures, inject `SpawnSetup` failures, removal/replacement of exact actor/anchor/Thing/cell after preflight, re-entry, save request inside staging, and failures before/after debit and during return credit and cleanup. Repeat both replay and conflict after reload. |
| Discovery and cap | Real player Pawn crosses an approach bucket, fog/reveal burst, no eligible actor, valid/invalid hour, inaccessible cell, rare opportunity replay on reload, repeated walk-out and blocked placement. | Spring, lure and nourishment regressions | `Alpha1`, `Alpha2`, `Alpha3`, `Alpha5A` and accepted 5B profiles. | Migration and add-ons | Load disposable derivatives of actual Alpha 5A, accepted 5B and supported V1/V2 fixture saves. Compare before/after counts, Scribe keys and individual GUIDs. Preserve unknown data, give one useful diagnostic, and restore safe participation only after revalidation. |
| Performance and graphical acceptance | Compare controlled counters and timing under the workloads above. Ensure bounded callbacks per tick, no per-tick world scan, reachable reveal, sensible hints, and ordinary capture experience. Keep owner play acceptance distinct from headless assertions or static analysis. |

| Abstraction and significance | Approve when ordinary wild encounters may leave play or aggregate, whether discovery/inspection alone makes a Gu significant, and which quest, rarity and custody events protect identity. Recommend preserving any captured, refined, quest-bound or unique individual, with a generous out-of-sight timeout and visibly grounded disappearance behavior for approved common wild Gu. Initially preserve all committed individuals on removal. |
| Regional definition and inactive evidence | Regional populations, bounded unloaded recovery and legitimate colonization are approved. Confirm the proposed evidence policy for healthy/destroyed sites and choose bucket boundaries, conservative evidence floor, catch-up cap and source priorities. |
| Spring profiles and farming content | Preserve established 5B ecosystems. Author the eligibility and weights for new ordinary and cultivated springs. Confirm proposed independently identified founding and valid provenance, choose a compatible artificial profile and define which introduced stock satisfies establishment. Milk-spout relocation remains deferred. |
| Balance and discovery | Tune minimum/maximum, 3–9-day ordinary recovery and the approximate 1–2-day founding target by species and season. Approve the first habitat signal, discovery affordance and scarcity. Supporting resources remain read-only for wild ecology. |
| Active relevance boundaries | Approve automatic encounters when colonists occupy an unselected loaded map, the status of visitors/NPCs on active maps, and recovery of rare habitat Gu from inaccessible levels. Recommend relevancy based on authorized actual presence. Detailed Gu hunger remains paused off-map as decided. |
| Upgrade and compatibility | Approve the supported save set, add-on and DLC matrix, and release commissioning on the accepted Alpha 5B commit. Decide whether to expand scope to permanent world sites or new host types once a concrete content slice requires them. |

The proposal follows the project's separation of species, populations and identity, and extends the published world-memory and multiple-origin principles. There are two tensions to review. The native registry currently equates active manifested Gu with Pawns, which blocks active rooted/stone Things until the loader and binding rules support them. The intended return of common Gu to populations is ahead of the current registry's return and compaction behavior. The proposed phases close each gap at its first concrete use, while preserving validated custody and legacy save ownership. [Vision](PROJECT-VISION.md) · [Schema V2 RFC](RFC-0004-GU-FRAMEWORK-V2.md)
