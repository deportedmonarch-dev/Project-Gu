# Alpha 6 baseline and engine audit

This audit covers Alpha 5A `d82c723769ab19dd9078ba3dfefd0a20ee8d10ce` in the isolated `Project-Gu-alpha6-research` worktree. The [architecture RFC](RFC-0007-WILD-GU-ECOLOGY.md) gives the design and the [implementation handoff](ALPHA-6-IMPLEMENTATION-AND-VERIFICATION.md) gives the delivery gates. The [readiness follow-up](ALPHA-6-ENGINEERING-READINESS.md) reconciles Alpha 5B and diagnoses the two initial Alpha 5A regression failures. The source at the pinned commit takes precedence where the architecture overview still describes V1 or earlier prototype species.

## RimWorld 1.7.5014 rev1195 interfaces

Direct inspection used the installed Windows `Assembly-CSharp.dll`, SHA-256 `11D7C9FAF52BE22933DA840D906B1AF7B48F7EA574A886C045B1FB12BD366124`, with ILSpy CLI 11.2.0.10050. The local binary establishes the method behavior below. Ludeon's announcement establishes the Waylith context. Decompiled bodies and game assemblies are excluded from the deliverables. [Ludeon 1.7 announcement](https://ludeon.com/blog/2026/10/announcing-the-waylith-engine-and-update-1-7/)

| Seam | Verified in the pinned assembly | Integration and native test still required |
| --- | --- | --- |
| Wildlife | `RimWorld.GenStep_Animals.Generate` calls `WildAnimalSpawner.SpawnRandomWildAnimalAt(IntVec3, bool, PawnKindDef)`. With no explicit kind the runtime pool comes from `map.BiomeAt(loc).AllWildAnimals`, season and local commonality. It then uses `PawnGenerator` and `GenSpawn`. `BiomeDef` handles pollution and coastal pools. In the fresh path `PawnGenerator.TryGenerateNewPawnInternal` calls `ThingMaker.MakeThing`, which calls `PostMake`. The generator can also choose an existing Pawn for redress. | No wildlife commonality entry, global spawner patch or implicit Pawn generation for Gu. Re-check the loaded Defs and all ordinary selectors, even with other mods active. Direct named calls fail at the Gu class guard, and explicit redress needs a separate regression fixture. |
| Map generation and loading | `MapGenerator.GenerateMap` adds the map to `Game` before executing content steps, then finalizes it and invokes `MapComponentUtility.MapGenerated`. Load also reaches `Map.FinalizeInit`, which calls component `FinalizeInit`. The engine also has an empty map path that finalizes without the generated-content callback. Component utility catches callback exceptions. | Use `MapGenerated` as a ready-to-initialize signal and `FinalizeInit` as a bind/rebuild signal, with a first safe tick that requires registry readiness and a live, eligible map. A `GenStep` is suitable only for fixed authored geography. Test custom generators, re-entrant/failed generation, native new game and fresh load. |
| Place, spawn and identity | `GenSpawn.Spawn` invokes `SpawnSetup` and may wipe existing Things according to its wipe mode. `ThingWithComps.SpawnSetup` and `DeSpawn` call `PostSpawnSetup(bool)` and `PostDeSpawn(Map, DestroyMode)`. `GenPlace.TryPlaceThing` distinguishes Direct and Near behavior. Native creation and placement call modded code. | Preflight a specific cell and revalidate the exact placed native object after callbacks. Registry staging must prevent UI/jobs from observing half-committed Gu. Never infer debit from native spawn success alone. Test blocker insertion, modded callbacks, placement failure and loaded native bindings. |
| Map signals and visibility | `map.events` exposes `ThingSpawned`, `ThingDespawned`, `TerrainChanged`, `RoofChanged`, `CellFogChanged(IntVec3,bool)` and other map events. `FogGrid.Unfog` sends a cell fog event even through bulk/initial unfog paths. Fog describes map knowledge, while a player's view and actor proximity are distinct. | Queue deduplicated dirty habitat cells and candidate discovery evaluations. Never commit or consume RNG per callback. Test new-map reveal, load rebuild, bulk reveal and one pawn walking out of sight of a clue. Proximity is a throttled map query for eligible actors. |
| Climate, regions and geography | `Map.Biome` reads `TileInfo.PrimaryBiome`. Native wildlife uses cell biome via `BiomeAt`. `PlanetTile` provides tile/layer context; `GenLocalDate` has map and PlanetTile hour/season overloads. `GenTemperature.TryGetTemperatureForCell` and tile/twelfth temperature APIs are available. `RegionGrid.GetValidRegionAt` can force a rebuild, while its `NoRebuild` variant can lack valid data. `Reachability.CanReach` accepts traversal parameters. | Use stable Project GU keys plus coarse tile/layer context. Keep regions/reachability as transient checks. Match cell and tile signals for mixed biomes. Supply an underground climate and geography strategy explicitly. Verify local season on hidden layers, irregular maps and custom habitat tags. |
| Plants | `GenStep_Plants` calls `WildPlantSpawner`. Growth can change while the Thing stays spawned. | Native spawning is suitable for ordinary supporting flora. Identity-bearing plant Gu require registered factories (including exclusions from native sow/stock/spawn paths) and explicit harvest/damage semantics. | Jobs and encounters | `Pawn_JobTracker.TryTakeOrderedJob` can call `TryMakePreToilReservations` before starting; `StartJob` also reserves. Job/driver state is exposed to Scribe and driver toils can be rebuilt. `IncidentWorker` offers a later eligibility/execution hook. Add dedicated incident workers only when the first local discovery works. Measure pawn needs/health/AI and collision/pathfinding at cap. |
| Teardown and world holders | `Game.DeinitAndRemoveMap` notifies the parent, runs `MapDeiniter.Deinit`, removes the map from the loaded list, and later calls component `MapRemoved` and parent notification. `MapDeiniter` handles pawns and tells native Things their map is being removed. `ThingWithComps` forwards the latter when `def.notifyMapRemoved`. `WorldPawns` and `Caravan` hold native objects outside a map. `TickManager.DoSingleTick` visits loaded maps even when another map is selected. | Snapshot before deinitialization via existing lifecycle bridge, with `MapRemoved` for transient cleanup. ## Evidence and baselines

- This campaign ran `scripts/verify.ps1 -Focused` on .NET SDK `10.0.401` against the installed 1.7 assemblies and Harmony. Structural checks, the game-linked mod build (zero warnings/errors) and isolated managed fixtures passed. The managed test project emitted existing `CS8632` nullable-context warnings. The managed run includes cohort migration/round-trip, alternate underground route/address fixtures, 64 layout and flora cases, generation exclusions, feeding, and refinement. It does not start RimWorld. [Verifier](../scripts/verify.ps1)
- The independent Core + Harmony campaign `312f092b8bde41ffba0305d5b98eb190` passed `GuGeneration` in a new game and fresh-process reload. It verified ordinary animal selection exclusions, direct factory refusals, a registered test identity and an old unbound pet. Its `Alpha5A` profile stopped in the Alpha 3 Arid Shrubland setup, before feeding, at the assertion that the no-beer lure option is shown and disabled. The assertion does not identify which of its menu conditions failed. [Generation fixture](../tests/ProjectGu.LiveVerification/LiveGuGeneration.cs) · [Lure assertion](../tests/ProjectGu.LiveVerification/LiveAlpha3.cs)
- In independent retry `ff02427632964621b295f11837a439b8`, the Temperate Forest `Alpha5A` run passed `new` and `feeding`. The fresh process matched the saved feeding state and job, consumed the resumed meal once, and passed both per-individual starvation checks and the immediate letter-count check. It then failed the combined global letter-count and per-Gu terminal-history assertion after two sweeps. The engine log reports two starvation endings. The later assertion alone cannot establish a duplicate death. `final` and `legacy` were unreached in both attempts. Both campaigns used disposable copies, and the runner reported zero copy or normal user-data changes. System event log access was denied, leaving runner timing validity unverified. [Feeding fixture](../tests/ProjectGu.LiveVerification/LiveAlpha5A.cs)

Published V2 lifecycle and underground reports cover native custody, world-site recovery, and route/abandonment behavior. These reports predate the proposed Alpha 6 surfaces.
