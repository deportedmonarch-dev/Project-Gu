# Project GU architecture

This document describes the framework and the developer-only implementation on the underground spring development branches. See the [roadmap](docs/ROADMAP.md) for verification and sequencing and the [project vision](docs/PROJECT-VISION.md) for design requirements.

## Implemented subsystems and save ownership

| Subsystem | Source and authority |
|---|---|
| Mortal status and awakening | [GuWorldComponent](Source/ProjectGu/GuWorldComponent.cs) is a GameComponent that deep-saves `guPawnRecords`. Records link to pawns via Scribe references and own latent aptitude and awakening status. The lookup is rebuilt after loading. Loaded-map pawn discovery runs every 600 ticks. The [awakening job](Source/ProjectGu/Jobs/JobDriver_GuAwakenAtSpring.cs) reserves its spring and invokes the service in the final toil. |
| Aperture | [Hediff_Aperture](Source/ProjectGu/Hediff_Aperture.cs) owns aptitude, rank, essence, and physique. The [Gu registry](Source/ProjectGu/GuIndividualRegistry.Aperture.cs) owns the one-slot custody claim and resolves the exact host Pawn and Hediff. A stored Gu has no physical projection. |
| Species definitions | [GuSpeciesDef](Source/ProjectGu/Domain/GuSpeciesDef.cs) and [XML Defs](Defs/GuSpeciesDefs/GU_GuSpecies.xml) supply rank ranges and descriptive tags through `DefDatabase`. The catalog contains Hope Gu, Moonlight Gu, and a developer test species. |
| Individual Gu | [GuIndividualRegistry](Source/ProjectGu/GuIndividualRegistry.cs) deep-saves canonical, versioned records under `guIndividualRecordsV1`. Development Pawn and dormant Thing projections save the Gu ID and binding revision. After map loading, the registry validates the exact native owner and excludes quarantined claims from its live indexes. [Dormancy](Source/ProjectGu/GuIndividualRegistry.Dormancy.cs) stages a reversible handoff and runs explicit discard after committing ground custody. [Slice 3B-2 verification](docs/IMPLEMENTATION-0.2.5.md#slice-3b-2--wild-gu-dormancy). |
| Spring ecology and production | Each [spring ThingComp](Source/ProjectGu/Springs/CompGuSpiritSpring.cs) owns reserve, production and habitat fields, a persistent habitat ID, and the deep-saved `guPopulationRecords025` list. The [ledger](Source/ProjectGu/Springs/GuPopulationLedger.cs) operates on the spring's list. Legacy population scalars are migration inputs or derived shadows. Species keys preserve unresolved add-on counts. Current gameplay updates the Hope Gu cohort only. The spring produces haulable stones from its own reserve. |
| Map ecology | The [map component](Source/ProjectGu/Springs/GuEcologyMapComponent.cs) holds transient spring subscriptions and attributes each physical patch to one eligible spring. Both native Plants and legacy Building flora invalidate local counts through ThingComp lifecycle callbacks. New caverns select native regrowth through `guUsesBotanicalFlora` and the revised field and output profile through `guCavernApproach`. Core owns native plant growth and sowing. The [spring](Source/ProjectGu/Springs/CompGuSpiritSpring.Flora.cs) credits physical plant counts according to species Defs and owns transient native lights for the field. |
| Underground levels | The [registry](Source/ProjectGu/Underground/GuPocketProbeComponent.cs) saves legacy native pocket bindings under `guPocketProbeSitesV1` and independent site, level and route records under `guIndependentUndergroundSitesV1`. A normal engine-saved MapParent owns each new spring level, and RimWorld owns the map and physical contents. One shared hidden world layer supplies native addresses. The [Priority 0 report](docs/UNDERGROUND-INDEPENDENT-LEVELS.md) tracks lifecycle policy and verification. |
| Passage hauling | A [WorkGiver](Source/ProjectGu/Underground/GuPassageHauling.cs) under the dedicated Underground hauling Work type discovers direct routes indexed under a pawn's surface map and starts map-local passage, pickup and storage jobs. Each enabled route permits one active worker or a named assignee. The site saves the worker, dispatch policy, rotation and packed reference under `passageHauling`. Native Pawn inventory owns the stack. Site Defs configure cargo. [Spring player controls](docs/UNDERGROUND-SPIRIT-SPRING.md#automatic-hauling). |
| Gu abilities and combat | The registry authorizes species abilities for an exact refined Gu in its cultivator's live aperture. The cast service revalidates at commitment and debits the aperture once. Native projectiles own flight and damage, and the ledger saves intents, cooldowns and outcomes. Channel jobs apply paid pulses and can retain an interrupted session for resumption. Sustained self-use abilities commit a native hediff directly and preserve the pawn's job. The hediff saves its exact granting binding and payment deadline. The ledger processes only active conditions before the normal tick list. Optional map effects follow live gameplay state. [Moonblade](docs/ALPHA-2-MOONLIGHT-GU.md) · [Liquor Worm](docs/ALPHA-3-LIQUOR-WORM.md) · [Stone Skin](docs/ALPHA-6-SLICE-1B-2.md#sustained-effects) |
| Aperture interface | The [Aperture tab](Source/ProjectGu/Interface/ITab_Pawn_Aperture.cs) is presentation only and saves nothing. It reads a per-refresh [ApertureView](Source/ProjectGu/Interface/ApertureView.cs) snapshot of the aperture, registry, ledger and jobs, and every control runs a [GuApertureAction](Source/ProjectGu/Interface/GuApertureActions.cs) that calls the existing authority, which revalidates and commits. The fallback Manage aperture Gu menu uses the same actions. [GuApertureRankDef](Source/ProjectGu/Interface/GuApertureRankDef.cs) holds rank terminology, stage colours and grayscale art recoloured by the [orb renderer](Source/ProjectGu/Interface/ApertureOrbRenderer.cs). Aperture vitality comes only from registered condition sources (none yet). [Refinement presentation](Source/ProjectGu/Presentation/GuRefinementPresentation.cs) attaches will-enforcement effects from the live job. [Alpha 4A](docs/ALPHA-4A-APERTURE-INTERFACE.md). |
| Gu sustenance | Species declare a [feeding policy](Source/ProjectGu/Domain/GuFeeding.cs) in XML (not implemented, exempt, or simulated with physical foods and a pluggable feeding worker). Nourishment is a `GuStateComponent` on the canonical record, settled lazily from absolute ticks by a bounded [scheduler](Source/ProjectGu/Sustenance/GuSustenanceComponent.cs); it follows the individual through every placement. Hunger advances only in player care on a loaded map. [Feeding jobs](Source/ProjectGu/Jobs/JobDriver_GuFeedGu.cs) consume items only at a revalidated commitment. Withering is refused at the ability-authorization boundary, and starvation death uses the terminal transaction with one event key per individual. [Alpha 5A](docs/ALPHA-5A-GU-FEEDING.md). |

The save-integrity follow-up preserves recoverable cohort data and disables mutation for ambiguous or invalid versioned lists. Phase F verified ordinary Hope Gu persistence in fresh-process native loads. Dedicated live coverage for ambiguous, missing and unresolved cohort entries remains open. [Implementation journal](docs/IMPLEMENTATION-0.2.5.md#phase-f-focused-regression).

## API evidence and open risks

- The player-tested 0.2.4 hotfix exercises a baseline using `ThingComp.PostSpawnSetup(bool)`, `PostDestroy(DestroyMode, Map)`, `PostExposeData()`, and `CompTickRare()`. The prior `PostDeSpawn(Map)` override failed in that target. Check signatures again on the game build used for a new change. See the [compatibility policy](docs/COMPATIBILITY-1.7.md) and [baseline release](docs/RELEASE-0.2.4.md).
- The 0.2.5 branch uses deep Scribe for cohorts and runs migration in post-load/spawn initialization. Player reports cover Slice 2 gameplay. Isolated engine fixtures cover legacy cohort migration. Native fixtures cover held Things in Pawn inventory, both passage directions, and fresh-process reload. [Phase F results](docs/IMPLEMENTATION-0.2.5.md#phase-f-focused-regression).
- Natural awakening commits one mature Hope Gu debit and the Pawn record together. The service holds a transient per-Pawn guard across native health callbacks and removes its provisional aperture if the attempt aborts before debit. Mortal status markers follow the committed record through normal discovery. See the [awakening verification](docs/IMPLEMENTATION-0.2.5.md#phase-b-awakening-conservation).
- Installed 1.7.5014 exposes `ThingComp.PostDeSpawn(Map, DestroyMode)`, which deregisters springs and invalidates flora support for removals. Habitat ID collision diagnostics are map-local. Full map removal and transfers still require live validation before habitat IDs become cross-map endpoints. See [GuEcologyMapComponent](Source/ProjectGu/Springs/GuEcologyMapComponent.cs).

## Proposed boundaries

**Schema V1 is provisional.** The [engine investigation](docs/ENGINE-1.7-GU-V2-INVESTIGATION.md) verified that V1 quarantines individuals when ordinary native events move or end them. [RFC-0004](docs/RFC-0004-GU-FRAMEWORK-V2.md) proposes Schema V2. The engine becomes authoritative for physical location, manifestation moves to a component, and lifecycle outcomes and recoverable unresolved states replace quarantine in ordinary play. [RFC-0005](docs/RFC-0005-CULTIVATORS-REFINEMENT-APERTURES.md) and [RFC-0006](docs/RFC-0006-PERSISTENT-IMMORTAL-ENVIRONMENTS.md) cover cultivators, apertures and environments. The [assessment](docs/V2-SYSTEM-ASSESSMENT.md) classifies each current component. On `feature/gu-framework-v2`, Phase 1 implements Schema V2. See the [V2 journal](docs/IMPLEMENTATION-V2.md). The description below is the V1 implementation on `main`.

Slice 3 uses record-backed identity with development Pawn and dormant Thing projections. The [inventory transfer](Source/ProjectGu/GuIndividualRegistry.Inventory.cs) moves the same Thing between the map and a colonist's exact native inventory. The [aperture transfer](Source/ProjectGu/GuIndividualRegistry.Aperture.cs) commits record-only custody before retiring that Thing and can stage a fresh native inventory projection for the same Gu on withdrawal. Each committed custody move advances the revision once. [Slice 3B plan](docs/RFC-0002-GU-INDIVIDUALS-AND-CUSTODY.md#slice-3b-implementation-plan).

[Active release](Source/ProjectGu/GuIndividualRegistry.Release.cs) stages a suppressed wild Pawn and validates placement before committing the exact native binding. [Map custody protection](Source/ProjectGu/GuIndividualMapCustody.cs) derives its result from live registry bindings and plugs into the independent underground route guards.

[Cohort materialization](Source/ProjectGu/GuIndividualRegistry.Materialization.cs) reuses the staged wild Pawn and commits one adult debit on the habitat's existing cohort. The individual record owns the event key, origin and debit evidence. The live event index rebuilds from those records.

The shared wild projection Defs exclude Gu kinds from native animal selection. The Gu Pawn's creation hook requires a registry permit for fresh bodies, and save loading reconciles existing projections against their canonical records. [Generation integrity policy and audit](docs/GU-GENERATION-INTEGRITY.md).
